# REGRAS DO PROJETO

Estas regras devem ser respeitadas durante todo o desenvolvimento.

---

# Regra nº 1

Nunca implementar código antes de compreender completamente o problema.

Sempre explicar a solução antes de codificar.

---

# Regra nº 2

Nunca alterar arquivos que não foram solicitados.

Modificar apenas o necessário.

---

# Regra nº 3

Antes de criar qualquer componente, consultar:

- PROJETO.md
- IDENTIDADE.md
- DESIGN_SYSTEM.md

---

# Regra nº 4

Nunca copiar templates.

As referências devem servir apenas como inspiração.

---

# Regra nº 5

Sempre priorizar:

- organização
- simplicidade
- performance
- manutenção

---

# Regra nº 6

Não adicionar bibliotecas sem necessidade.

Preferir sempre soluções nativas.

---

# Regra nº 7

Tecnologias permitidas

- Django
- HTML
- CSS
- JavaScript

Não utilizar:

- React
- Vue
- Angular
- Bootstrap
- Tailwind

Sem autorização.

---

# Regra nº 8

Toda animação deve possuir um motivo.

Não criar animações apenas por estética.

---

# Regra nº 9

Sempre desenvolver Desktop First.

Depois:

- Tablet

- Mobile

---

# Regra nº 10

Todo código deve ser:

- organizado
- comentado quando necessário
- reutilizável
- legível

---

# Regra nº 11

Sempre pensar como UX Designer antes de pensar como desenvolvedor.

---

# Regra nº 12

Quando houver dúvida entre duas soluções:

Escolher a mais simples.

---

# Regra nº 13

Performance é prioridade.

Menos código.

Menos JavaScript.

Mais CSS.

---

# Regra nº 14

A identidade visual nunca pode ser quebrada.

Todo novo componente deve seguir:

- DESIGN_SYSTEM.md
- IDENTIDADE.md

---

# Regra nº 15

Antes de concluir qualquer tarefa verificar:

- responsividade

- alinhamento

- acessibilidade

- consistência visual

- performance

# REGRAS PARA ASSISTENTES DE IA

Sempre:

- Leia toda a documentação antes de responder.
- Explique o motivo das decisões.
- Não faça alterações desnecessárias.
- Preserve a consistência do projeto.
- Não reestruture pastas sem autorização.
- Não renomeie arquivos existentes.
- Não altere tecnologias definidas no projeto.
- Priorize soluções simples.
- Pergunte quando houver dúvida relevante.
